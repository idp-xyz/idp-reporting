# 单据 PDF 引擎对比：Typst 与 Go 自研版式（fpdf）

## 验收阈值（在运行对比之前写下并提交）

两个引擎使用同一套检查（spikes/pdfeval/eval.py）、同一份生成数据和同样的单据要素。同样的参数下，两个程序生成的数据文件必须逐字节一致，否则对比无效。

硬性阈值（任何一项不满足即不合格）：

| 编号 | 要求 |
|---|---|
| H1 | 正确性：所有规模下每行恰好出现一次、顺序正确；每页都有表头和"第 X 页 / 共 Y 页"；每页的承前页、过次页金额与独立重算一致；末页的合计和人民币大写正确 |
| H2 | 不静默丢数据：所有摘要文字都完整、原样出现在 PDF 中，包括比一页还高的行。如果做不到，必须拒绝渲染 |
| H3 | 恶意字符串按原样显示，不被执行 |
| H4 | GB/T 15834 避头尾：压力测试 0 违例 |
| H5 | veraPDF PDF/A-2b 通过；不开 PDF/A 的对照版本不通过 |
| H6 | 同一输入两次输出逐字节一致 |
| H7 | 只嵌入指定字体，中文可以复制和搜索 |

暂定阈值（业务的页数分布、并发和内存预算尚未提供，数值待确认）：

| 编号 | 要求 |
|---|---|
| P1 | 约 1000 页单据的峰值内存 ≤ 1GB |
| P2 | 约 1000 页单据的耗时中位数 ≤ 10 秒（重复 5 次） |
| P3 | 4 路并发渲染约 100 页单据，全部成功 |

另外记录但不设阈值：开发量（代码行数、需要自己实现的能力）、运行时依赖、沙箱要求、文件大小。
