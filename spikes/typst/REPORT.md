# Typst 作为单据/报表 PDF 引擎的评估

2026-10-27（Asia/Shanghai）。分支 spike/typst-pdf，基于 reporting-s03a（cf9960e）。
本目录是独立 Go 模块（仅标准库），不进入主模块构建，不改动任何业务代码。

## 结论

**可以采用 Typst，但有四个前提**，缺一不可：

1. **Typst 只负责排版，不做业务计算。** 每行金额、逐行累计和合计都由 Go 用精确大数算好，以字符串传入。模板只显示这些字符串，最后校验"末行累计 = Go 合计"，不一致就中止渲染。这样既符合"业务精度不经浮点"的规则，也避开了 Typst `decimal` 约 28 位的精度上限。
2. **必须在断网沙箱里运行。** Typst 没有离线开关：模板里写 `#import "@preview/…"` 会在渲染时从网络下载第三方包并执行（实测下载了 cetz 及其依赖 oxifmt）。本原型让 Typst 运行在独立的、没有网卡的用户和网络命名空间里，导入因此被拒绝。需要用的包要预先审核，放进 `--package-path`。
3. **必须限制时间和内存。** Typst 本身没有超时机制，而且整份文档常驻内存：表格页约 2–3.3MB/页，千页约 2.7GB。建议单份限制在约 300 页（约 1GB），超出就自动分册，或者走单独的大文档队列并配内存配额。
4. **用户不能直接写 Typst 源码。** 模板本身就是代码。建议模板设计器只生成受限的模板，Typst 源码由服务端生成。

满足这四点后，分页能力（表头重复、承前过次、页码共 Y 页）、PDF/A-2b、确定性输出和中文避头尾都可以直接用，省去自研版式引擎的大部分工作。

## 实测结果

环境：Typst 0.15.1（官方 musl 静态二进制，sha256 校验通过）；Noto Sans SC 2.004（OFL，只用 Regular 和 Bold）；veraPDF 1.30.3（官方镜像，断网运行）；Linux x86_64。原始数据在 results/results.json。

| 评估项 | 结果 |
|---|---|
| 分页正确性 | 150、400、3000、30000 行四个规模下：每行只出现一次且顺序正确；每页都有表头和"第 X 页 / 共 Y 页"；**每页的承前页、过次页金额都与独立重算一致**（最大 831 页） |
| 精确金额 | 16 位整数的合计精确显示，人民币大写正确；30 位的合计在 Go 层拒绝渲染 |
| 恶意字符串 | `#panic(...)`、`$x^2$`、`<script>`、`#read("/etc/passwd")`、`]`、`\` 等都按原样显示，没有被当作代码执行 |
| 中文避头尾（GB/T 15834） | 1485 行长摘要压力测试中 0 违例。原生行为下，首轮压力测试里间隔号"·"会落在行首（首轮记录只保留前 8 条，确切次数未知），加一条模板规则 `show regex("[^\\s]·"): box` 后消除。破折号、省略号都没有被拆开 |
| 字体 | 只嵌入 Noto Sans SC 子集（CID），没有回退到其他字体；中文可以复制和搜索 |
| 确定性 | 同一输入、同一时间戳两次渲染，逐字节一致；sample.pdf 在两次独立的评估运行之间也一致 |
| PDF/A-2b（veraPDF） | 正式样例 PASS，带草稿水印的 PASS；不开 PDF/A 选项的对照版本 FAIL |
| 性能（单机单次） | 1 页 0.027 秒、39MB；84 页 0.82 秒、311MB；831 页 8.5 秒、2.70GB。三个规模的全部检查都通过 |
| 读取根目录外文件 | 被拒绝，路径会被限制在根目录内 |
| 死循环、无限递归 | 字面量 `while true` 会被静态拒绝；无限递归报"超过最大调用深度"。其他形式的长循环 Typst 不会自己停止 |
| 耗时模板 | 由封装层在 3 秒时杀掉 |
| 内存上限 | 96MB 地址空间下渲染失败并报错，失败得干净 |

### 两个性能对照

- 承前过次最初写成"每页查询之前的所有行"，复杂度 O(n²)，831 页要 13.2 秒、3.86GB（见 results-per-page-query-variant.json）。改用 `state` 逐行更新，并在页眉页脚取当前值后，降到 8.5 秒、2.70GB。**模板写法对性能影响很大**，模板生成器必须避免全文查询。
- 同样 30000 行，一张大表：770 页、5.2 秒、1.86GB；拆成 60 张小表：771 页、4.6 秒、1.66GB。内存基本随页数线性增长，是 Typst 整份文档常驻内存的固有特性，拆表只能省约 11%。

## 已知不足（未解决）

- **标点挤压**：相邻全角标点（如"》（"）没有挤压，属于美观问题。可以尝试开启字体的 `chws` 特性，但未验证。
- **中英文自动间距**：Typst 默认在中文和数字、字母之间加空格（"共 12 件"）。可以用 `cjk-latin-spacing: none` 关闭，按企业规范选择。
- **大文档内存**：见上，需要限制页数或分册。
- **版本升级会影响分页**：必须固定 Typst 版本；升级时用一组标准样例做回归比对，检查页数和分页位置。

## 未验证

PDF 阅读器兼容性（Acrobat、浏览器内置阅读器等；只用 PyMuPDF 和 veraPDF 检查过）、套打（按预印纸精确定位）、竖排、条码和二维码、多语言混排、并发渲染、跨机器的确定性（只在同一台机器上验证）、Windows 和 macOS 版 Typst、真实业务数据。

另外，PyMuPDF 是 AGPL 许可，这里只作为测试工具使用，不随产品分发。

## 复现

依赖（不入库，用 sha256 固定）：
- Typst 0.15.1 `typst-x86_64-unknown-linux-musl.tar.xz`：a6d077d0a95eed5a2eba715b2dae06be954f624ccbf85758a03f389ded33118c
- Noto Sans SC，发布包 Sans2.004 `18_NotoSansSC.zip`：4d107c09ada479d3e48b6e78c83835773cbd9214bf6e12cdb7b60f8e068292ec；Regular faa6c9df…5ea9，Bold c6cb5a93…67c0
- veraPDF 镜像 `verapdf/cli:v1.30.3`，镜像 ID sha256:7abe7b3db1be0af496fbbbda0b0784efe7f7ebb4083fbb0453b245c96b5d7b05
- PyMuPDF 2.0（Python 虚拟环境）

```bash
go test ./... && go build -o typst-spike .
python -I eval.py --spike-bin ./typst-spike --typst <typst> --fonts <只含 Noto Sans SC 的目录> --out results
```

需要非特权用户命名空间（`unshare -rn` 可用）和 Docker（用于 veraPDF）。这台机器上 Docker 守护进程不走代理，所以 veraPDF 镜像是用一个脚本经 shell 代理逐层下载、校验 sha256 后 `docker load` 进来的，没有改动系统配置。

## 文件

- main.go：数据生成、精确金额、调用 Typst（断网命名空间、空包目录、固定字体、超时、可选内存上限）
- rmb.go、rmb_test.go：人民币大写（最多 16 位整数，超出拒绝）
- statement.typ：单据模板
- eval.py：全部自动检查
- results/：结果数据、样例 PDF 和页面渲染图
