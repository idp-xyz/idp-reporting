# IDP Reporting Platform · S00 架构基线 V1.0

日期：2026-10-26（上海时间）。状态：独立化设计基线；不是生产实现验收。

## 需求与工程判断

用户已明确多个软件产品需要共用报表平台。目标为独立安装、运行、升级、扩容与管理的
报表及单据平台，Brant 是一个接入产品。平台有独立控制台，也提供嵌入产品的展示与设计入口。
共用部署与客户专用部署使用同一平台实现；每产品复制一套核心不是目标。

采用“独立部署的模块化平台＋外部业务适配器”。内部先保持 Go 模块化核心、任务 Worker、
Node.js/pdfme 渲染进程和平台自有元数据/产物存储；不把目录、查询、模板等逐项拆成微服务。
独立平台是针对多产品共用需求的工程选择，尚不能由文档或旧测试证明实现已独立。

| 方案 | 适用性与代价 | 决定 |
|---|---|---|
| 每产品内嵌一份报表核心 | 初期接入较快；升级、缺陷修复和权限行为易出现多份差异 | 不作为共享平台主形态 |
| 独立平台、内部模块化、产品适配器 | 支持独立发版；需要真实的身份、数据及授权契约 | 本轮设计基线 |
| 初期全面拆成微服务 | 需要额外处理分布式运维与版本协调；目前无相应负载证据 | 有证据后再评估 |

## 职责与所有权

平台负责目录与定义版本、受控查询、结果快照、通用表格/图表、Excel/PDF、模板设计与发布、
任务、私有产物、审计和运行限额。平台执行经批准的指标定义；指标业务意义由产品负责人维护。
来源产品负责事实、业务字段/口径、当前业务权限、金额计算、审批、编号和正式出具确认。
平台保留正式文件及内容版本，不独立批准业务单据或修改交易事实。

平台运行代码和数据库迁移不得依赖 Brant、Parcel 等产品的私有包、业务表或交易运行时。
平台只拥有目录、模板、任务、快照、产物引用与审计数据；来源业务事实通过版本化接口接入。
平台可以保存有生命周期的授权投影/结果，不把它变成来源产品的第二份交易权威。
BIP、EER、HOST、CMI、MCP 均为可选适配方向，不是独立运行的先决条件。

## 两类产品接入

首个适配器迁移 Brant 应收账龄及其已验证口径；第二个选择非外贸财务领域的数据，例如 Parcel
运单统计。第二产品尚未取得真实数据合同，示例只是协议设计与后续测试模拟器，不能声称已接入。
初期让多个产品分别查询和导出；跨产品联合分析另行定义关联映射、语义与共同数据时点。

## 当前证据与状态

R01-D 是旧 Brant 测试配置下的真实工程证据：31 个报表数据库用例、12 个 Bento 顶层测试
各完成普通/race 两轮，根模块146个顶层测试通过。其代码和证据保持原样。
这些结果不等于独立平台、多产品隔离、通用指标目录或两个真实产品适配已通过。
本轮只产出架构、接口草案、迁移顺序和验收清单；S01及后续代码验证尚未执行。
Brant 的 G00 是其业务工程门禁；平台有独立生产准入，各来源产品分别通过接入资格。
