# S00 → S01 迁移与验证顺序

## 第一个可执行切片：S01-A

交付一个不依赖 Brant 仓库即可编译、启动、测试的最小平台后端，两个不同领域的合同模拟
适配器使用同一通用核心；第二适配器接入不能修改通用核心。先覆盖目录→查询→异步快照→
XLSX→取消/撤权/下载，保留原子发布与 lease fencing。此时只通过工程模拟器验收，不称为
两个真实产品接入完成。不得直接删除旧测试库保护或把合成身份切成生产身份。

| 现有位置 | 处理 |
|---|---|
| internal/reporting 的快照、游标、任务机制 | 迁入独立核心并扩展产品隔离；重新执行相应行为测试 |
| internal/costing/evidence 的严格 JSON 依赖 | 迁移所需通用能力到平台自己的中立包；核心不得继续导入 Brant 私有路径 |
| ValidateQuery、RequiredFields、固定 Row | 业务验证移至 Brant 目录/适配器；核心改为已批准目录驱动的类型化结果 |
| pgstore 的账龄 SQL 与来源事实表 | 移至 Brant 接入实现或合同模拟器，平台元数据库只保存自身运行资产 |
| pgstore 任务、lease/CAS 和文件完整性机制 | 按平台身份与产品隔离迁移；重新做真实 PG 并发/恢复测试 |
| DemoBearer、固定 alice、brant_test_* 守卫 | 原配置保留作历史测试；新平台有自己的认证适配与受保护的测试引导，不直接替换为生产凭据 |
| integration/reporting/go.mod 的本地 replace | 独立模块不得依赖 Brant 根模块；业务适配器从产品侧调用版本化接口 |
| xlsx、pdfme、ArtifactStore | 保留选型与可复用机制；通用类型、资源/模板治理与生产存储仍需阶段验证 |

## 后续里程碑

- S01-B：独立平台自有 PG 测试迁移、普通/race、跨产品/跨租户、并发、撤权、真实重启与文件校验。
- S02：接入真实身份和 Brant＋第二产品的真实只读数据合同；验证无服务账号越权、字段/金额/数量对账与接口版本兼容。
- S03：独立控制台及嵌入层；目录/报表/看板定义与三个设计器按能力逐项验收；正式单据保留来源产品的审批与出具确认。
- S04：生产迁移/升级、私有对象存储、清理/重试/配额、容量、最小权限、备份与故障恢复；通过后才讨论生产准入。

## 范围控制

先验证接口，再扩大功能。通用 DSL 只覆盖已发布能力，不承诺任意 SQL、任意跨库关联或
未知财务表达式。平台独立部署不要求每个内部模块都成为微服务。前端框架、SSO厂商、
部署规模及生产容量目标在有现有资产和实测资料时确定，不由本基线假定。
