# 任务基线：S06-C → S07-A → S07-B

2026-11-04。`scripts/ux_baseline_s07.mjs` 在同一台 Windows Chrome（CDP，真实鼠标与键盘）上对同一个演示服务跑五个任务，记下人为每个任务付出的代价：点击数、输入的文本数、页面切换数（一个区段取代另一个）、壳子切换数（页面周围的外壳被换掉：控制台外壳 ↔ 文档工作室 ↔ 模板中心 ↔ 看板工作室）、打开的对话框数、死胡同数（页面让人先去别处，或拒绝后要人先做另一件事再回来）。它不评判外观与速度。脚本是自适应的：导航在屏幕上就点导航，否则走当前壳子给的出口；看板起始卡上是哪个按钮就点哪个；发布时先按“发布”，被拒绝就按旧路走（保存、再发布、再确认），被提供“保存并发布”就按它——同一条路，人怎么走它就怎么走。三组数字是同一版脚本在三个构建上量的：`evidence/s07a/baseline-before.json`（main 789b293，S06-C）、`baseline-after.json`（S07-A，0533ec9）、`baseline-after-s07b.json`（S07-B）。

每格三个数依次是 S06-C → S07-A → S07-B。

读法：

- T2（空会话里发布一个看板）：S06-C 要被起始卡送回工作台，再被“发布”拒绝一次（先保存），两个死胡同；S07-A 起始卡就地开数据抽屉，剩一个死胡同（发布拒绝）；S07-B 的“保存并发布”把它也去掉，11 → 9 次点击。
- T4（从任务面板看快照结果）：S07-A 的应用栏把页面切换从 5 减到 3；S07-B 的任务面板在当前页上拉开，再减到 1（面板算一个对话框）。
- T5（三个设计面之间来回）：S07-A 的应用栏 7 → 4 次点击，之后不变。
- T1、T3 基本不变：工作台本就是数据所在的页面；复制的样例已是干净的保存版本，发布本来就是一步。

没有改变的：输入数（5）；壳子切换仍有 8 次——三个全屏盒子还在各自换壳；对话框数在上升（3 → 4 → 5），因为抽屉和面板都算对话框，这是用对话框换页面切换的结果。要不要把三个全屏盒子装进同一个壳子，是 ADR 0009 §5 剩下的问题，看设计者的真实任务再定。
