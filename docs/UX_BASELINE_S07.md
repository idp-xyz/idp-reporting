# 任务基线：S06-C 之后与 S07-A 之后

2026-11-04。`scripts/ux_baseline_s07.mjs` 在同一台 Windows Chrome（CDP，真实鼠标与键盘）上对同一个演示服务跑五个任务，记下人为每个任务付出的代价：点击数、输入的文本数、页面切换数（一个区段取代另一个）、壳子切换数（页面周围的外壳被换掉：控制台外壳 ↔ 文档工作室 ↔ 模板中心 ↔ 看板工作室）、打开的对话框数、死胡同数（页面让人先去别处）。它不评判外观与速度。脚本是自适应的：导航在屏幕上就点导航，否则走当前壳子给的出口；看板起始卡上是哪个按钮就点哪个——同一条路，人怎么走它就怎么走。数字在 `evidence/s07a/baseline-before.json`（main 789b293，S06-C）与 `baseline-after.json`（S07-A）。

读法：

- T2（空会话里发布一个看板）：之前要被起始卡送回工作台、查询、再回看板，3 次页面切换、3 次换壳、1 个死胡同；现在起始卡就地打开数据抽屉（多了 1 个对话框），页面不换。点击数相同（10）：抽屉本身要打开一次，省下的是来回。
- T3（样例变成自己的模板）：模板中心不再因缺快照拒绝（之前靠预览已经够，没有计入死胡同），少了一次页面与换壳。
- T4（从任务工作区看快照结果）：应用栏让“去工作台、去任务、回工作台”各一步，页面切换 5 → 3，点击 6 → 4。
- T5（三个设计面之间来回）：之前每一步都得先退出当前壳子再进下一个（7 次点击、7 次换壳），现在应用栏一步到位（4 次：三个目的地加“返回设计器”）。
- T1 不变：工作台本就是数据所在的页面。

没有改变的：输入数（5）；对话框数反而 3 → 4，因为数据抽屉是对话框。壳子切换仍有 8 次，因为三个全屏盒子还在各自换壳——这是 ADR 0009 §5 留给下一步的问题，要不要把它们装进同一个壳子，看这组数字和设计者的真实任务再定。
