读法：

- T2（空会话里发布一个看板）：S06-C 要被起始卡送回工作台，再被“发布”拒绝一次（先保存），两个死胡同；S07-A 起始卡就地开数据抽屉，剩一个死胡同（发布拒绝）；S07-B 的“保存并发布”把它也去掉，11 → 9 次点击。
- T4（从任务面板看快照结果）：S07-A 的应用栏把页面切换从 5 减到 3；S07-B 的任务面板在当前页上拉开，再减到 1（面板算一个对话框）。
- T5（三个设计面之间来回）：S07-A 的应用栏 7 → 4 次点击，之后不变。
- T1、T3 基本不变：工作台本就是数据所在的页面；复制的样例已是干净的保存版本，发布本来就是一步。
- T6（在 T4 留下的结果上调整布局并发布）：报表布局设计器还没有 S07-B 给两个工作室的“保存并发布”。按“发布”先因为没有保存版本被拒绝一次，保存后再按，又因为没读发布状态被拒绝一次，读取后第三次才发布：两个死胡同，8 次点击，其中 4 次是被拒绝逼出来的。两次拒绝显示的都是“请检查数据集、公司范围及数据时点。”（`app.js` 的 `layoutAction` 把拒绝当作 400 INVALID_REQUEST），页面没有说要先保存或先读取发布状态；脚本知道下一步，人要自己猜。S07-G（ADR 0011）：布局设计器有了和两个工作室相同的“版本 · 保存版本 · 发布”，“发布”打开发布前确认并给出“保存并发布”，一步做完保存、读取发布状态和发布：8 → 5 次点击（报表、展开设计器、上移、发布、保存并发布），死胡同 2 → 0，多一个对话框（发布前确认）。
- T7（看一个数据集的字段、类型与币种，再用它查询预览）：在 main 上要先去数据中心看字段卡片，再按卡片上的“打开工作台”回来查询：3 次点击（数据、打开工作台、查询预览），2 次页面切换。S07-H 把数据中心并进数据抽屉之后，字段应该在抽屉里看，不离开当前页；ADR 0011 的要求是 T7 不比现在贵。S07-H：字段在数据抽屉里，所选数据集下方，就在查询面板旁边：2 次点击（数据芯片、查询预览），不切换页面，多一个对话框（抽屉）。
- T1（S07-H）：登录后就在报表工作台，不用再从概览点过去：4 → 3 次点击，1 → 0 次页面切换。新的 `openPage` 在 main 上也替 T2 省了一次点击（T2 登录后去看板之前要先到工作台，main 上量的是 8，旧脚本是 9），所以 main 的合计是 33 而不是 34。

没有改变的：输入数（5）；壳子切换仍有 8 次——三个全屏盒子还在各自换壳；对话框数在上升（3 → 4 → 5），因为抽屉和面板都算对话框，这是用对话框换页面切换的结果。要不要把三个全屏盒子装进同一个壳子，是 ADR 0009 §5 剩下的问题，看设计者的真实任务再定。

S07-F（ADR 0010，一个壳子）：控制台页眉留在每个页面上，三个全屏盒子在它下面、应用栏右侧；壳子切换 8 → 0，其余各数不变——这一刀只去掉“换一套页眉”的代价，不改变任何一步操作。壳子的计法同时改为“屏幕上的页眉是否换了”（`scripts/ux_baseline_s07.mjs` 的 `shellOf`：控制台页眉在屏幕上即为控制台壳子），在 S07-F 之前的构建上，这个计法与按 body 类名计得的数相同（8）。
