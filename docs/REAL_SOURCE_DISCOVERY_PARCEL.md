## 2. 后端是什么

- Go 1.26 的模块化单体（`go.mod`：`go.idp.xyz/idp-parcel`），16 个命令，其中 `cmd/parcel-api` 是 HTTP 服务、
  `cmd/parcel-dispatch` 负责 outbox 派发与定时任务，其余是登记用的命令行工具。约 4,300 个 Go 文件，其中约 2,270 个是测试。〔核〕
- PostgreSQL 16，12 个 schema、357 份 SQL 迁移（主线 13 个、387 份），显式 SQL，没有 ORM。〔核〕
- 持久化是真的数据库，不是内存或 mock。〔读〕工作区里 2026-10-28 的运行日志记录了用合成租户走通的一轮：提交、受理、
  收寄、交接、交付、客户费用确认（`CONFIRMED`）、对账单发布、供应商应付，另有关务、退运与取消。〔核：日志文件在，含确认记录〕
- **没有部署，也没有真实租户。** 仓库里只有测试用的 `compose.yaml` 与演示用的身份提供方配置，没有 Dockerfile、编排清单
  或生产迁移入口；`parcel-api` 用 `ListenAndServe` 监听明文 HTTP，进程内没有 TLS。〔核〕数据都是 `SYN-` 前缀的合成租户，
  演示库在内存盘上。〔读〕

## 3. 报表会用到的数据

运单头是“委托”（`parcel_shipment.shipment_request`），物理件是“包裹”；没有独立的包裹主表，件级事实分散在各上下文按
`(tenant_id, parcel_id)` 登记的表里。〔读〕与报表直接相关的：

| 表 | 一行是什么 | 报表关心的列 | 注意 |
|---|---|---|---|
| `parcel_shipment.shipment_request` | 一份委托，就地更新 | 状态（已提交 / 已受理 / 已拒绝 / 已撤回）、`submitted_at`、客户账户、申报包裹数组 | 受理决定、申报重量尺寸只在 JSONB 快照里，可缺 |
| `parcel_shipment.intake_adoption`、`final_outcome`、`parcel_cancellation` | 包裹的收寄、终局、取消，带版本 | 事件种类、发生时刻、是否当前版本 | “已发运”“在途”不是存储值，要从这些表推出 |
| `settlement_accounting.customer_charge` | 一笔客户费用，确认时更新 | 费用项目、阶段（预估 / 暂估 / 已确认）、原币与结算币金额（`bigint` 最小币单位，逐行带币种）、`confirmed_at`、`attribution_date`、责任法人、结算账户 | `attribution_date` 只在已确认时有值〔核：迁移 0045 的约束〕；金额恒为正，调整与贷项在别的表 |
| `settlement_accounting.customer_statement` | 一张已发布的对账单 | 账户、期间、币种、合计、发布与作废时刻 | |
| `settlement_accounting.supplier_expected_cost` | 一个成本版本 | 双币种金额、版本链 | |

- 时间一律是 `timestamptz`，输出为 UTC。业务日界只在结算一侧有：按结算账户登记的时区与截单时刻形成 `attribution_date`。
  没有租户级的报表时区。〔读〕
- 层级是 租户（物流集团）→ 责任法人 → 货主客户账户。〔读〕

## 4. 身份与授权

- `parcel-api` 自己验证三类 OIDC 令牌（操作者、集成客户端、首方客户端）：RS256 / ES256，`iss` 逐字比较，`aud` 含本部署
  的受众；身份是 (iss, sub)。仓库不带身份提供方，演示用本机的 Dex。〔读〕
- 一个操作者 (issuer, subject) 绑定唯一一个租户；授予按能力面登记、带生效区间，撤销另记一表；每个请求现读库、没有缓存，
  所以撤权在下一个请求生效。〔读〕这正是来源协议要的“按当前权利裁决”。
- **操作者的权限只到租户一级**，没有法人或客户账户维度。委托查阅按“租户 + 可见客户账户集”过滤，但目前只对合成租户接通。〔读〕
- **没有“受信服务替某个人断言身份”的通道。** 来源协议的每个请求都由平台用服务凭据发出、在 `context` 里写明
  (平台租户, issuer, subject)，由来源映射成自己的操作者。Parcel 现在只接受本人持有的令牌，注释与它的 ADR-0100 都写明
  身份不来自请求内容。这是接入要新开的一个口，按 Parcel 的惯例要先出它自己的 ADR。〔读〕

## 5. 与来源协议的差距

四个操作都要在 Parcel 一侧新写，领域逻辑不用动。

| 操作 | 现成的 | 要新写的 |
|---|---|---|
| `catalog` | 各登记册的排序与筛选声明；操作者的授予判断 | 数据集、指标、版本的登记；时区与币种政策；按主体裁剪 |
| `reads` | 事务框架；各上下文的读适配器 | 查询校验与 `query_hash` 复算；参数化的筛选与排序；汇总 SQL；冻结读取的存储与 TTL |
| `pages` | 游标的做法 | 从冻结的行取页；每页相同的合计；逐页复核授权 |
| `authorize` | 逐请求读库的授予判断；撤销表 | (平台租户, issuer, subject) 到操作者的映射；报表的能力面；公司范围的复核 |

- **冻结读取必须落到 Parcel 自己的表里。** 现有的读取都是实时的：分页游标读的是当前数据，框架只开 READ COMMITTED，
  委托状态、费用阶段、终局的“当前版本”都是就地更新，过去某一刻的状态无法从表上重建。一次读取不超过 1000 行，可以在
  `reads` 的一个语句里读出并存下，之后各页只读这份。〔推〕
- HTTP 层基本能出协议要的严格 JSON（金额已按字符串、时间已是 RFC 3339 UTC、解码已拒绝未知字段）；要补的是协议的错误体、
  拒绝重复键与 `null` 的解码、服务凭据的校验、TLS，以及记录 `X-Request-Id` 的访问日志。〔读〕
- 规模：中等（一个接入口、一套冻结存储、四到五个处理器、两三个汇总读取，加测试）。算上 Parcel 的 ADR 与一个能部署的
  HTTPS 环境则偏大。〔推〕

## 6. 第一批数据集的候选

三个都是单个上下文、一条 SQL 能出的汇总；逐行清单过不了 1000 行的上限，也过不了平台现在的类型（见第 7 节）。口径都要
Parcel 确认，以下是提议。〔推〕

| | A 已确认的客户费用，按归属日 | B 委托的日计数 | C 件级事件的日计数 |
|---|---|---|---|
| 来源 | `customer_charge`，阶段为已确认 | `shipment_request` | `intake_adoption`、`final_outcome`、`parcel_cancellation` |
| 维度 | 责任法人、结算账户、费用项目、归属日 | 责任法人、客户账户、提交日、当前状态 | 责任法人、客户账户、事件日、事件种类 |
| 指标 | 笔数；结算币金额（小数位随币种） | 委托数；申报包裹数 | 包裹数 |
| 必填筛选 | 归属日区间 | 提交日区间 | 事件日区间 |
| 口径提醒 | 是已确认的应收，不是收入、实收或成本；不含预估、暂估、调整与贷项；归属日按账户时区与截单时刻算；一个数据集只能一个币种 | 头数与申报件数是两个指标，不能与件级事实连接后相加；已提交不等于已受理；日界的时区要另行声明 | “发运”要点名取哪一个事实；“签收”只数当前版本；同一件会出现在多个种类里，种类之间不能相加 |

建议先做 A：它是 S02-A 以来“应收”这个主题第一次有真实台账可读，口径最清楚（已确认的费用、归属日、币种都是存下来的值），
而且金额能与 Parcel 自己的对账单合计对账。

## 7. 平台的数据模型缺什么

这次核对把设计评审里说的三个缺口落到了具体的列上，ADR 0028（提案）据此而写：

- **空值**：未确认费用的 `confirmed_at` 与确认各项、判不出的 `attribution_date`、未申报的尺寸、未终局包裹的签收日、
  受理前的法人与决定时刻。平台的 `date`、`integer`、`decimal`、`boolean` 单元格现在不能为空。
- **时刻**：`submitted_at`、决定时刻、收寄与交付的发生时刻、对账单的发布时刻。平台只有 `date`。
- **指标能不能相加**：C 的各事件种类之间不能相加，B 的两个计数不能与件级事实相加；平台的布局小计会把指标列直接相加。

   Parcel 的授权模型的决定，写进 Parcel 的 ADR。

还要产品负责人定的：

3. **身份怎么对上。** 报表平台的发行方与 Parcel 操作者的发行方是不是同一个（同 `iss`、同 `sub`），否则要一张映射表；
   平台租户与 Parcel 的 `tenant_id` 怎么对应。
4. **环境。** 没有部署就没有地方跑 `reporting-source-check`，也没有可对账的真实数据：预发环境与第一个真实租户何时有。
   在那之前只能对着 Parcel 的代码和合成租户证明协议，不能做真实对账。

接入时与 Parcel 一起定的：

5. 时点的含义：就地更新的表无法重建过去的状态，每个数据集要写明“时点只筛业务日期，状态取冻结那一刻”。
6. 多币种：按币种拆数据集，还是把币种作为必填筛选。
7. “发运”“签收”的取数事实，更正与版本链只数当前版本，取消的三种走向。
8. 超出 1000 行时来源回答哪个错误码（协议没有写明），以及日期窗的上限。
