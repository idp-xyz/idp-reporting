# ADR 0001: PDF engine

2026-10-27. Status: accepted by the product owner. Supersedes the earlier choice of a Go-native layout on
codeberg.org/go-pdf/fpdf.

## Decision

Render PDF documents with a pinned Typst CLI (0.15.1 at the time of writing), run as a separate process,
under these conditions, all of which are part of the decision:

1. Go computes every amount, running total and capital-numeral text exactly and hands Typst strings in a
   JSON data file. Typst only lays them out; templates never compute business values.
2. Go checks, before rendering, that every character to be printed is covered by the configured fonts, and
   fails closed (or uses a configured fallback font) otherwise. No engine may be trusted with this.
3. Typst runs with no network (an empty user and network namespace, or a container without network), an
   empty package store, only the configured fonts, a private root directory, a timeout and a memory limit.
   Typst has no offline switch and downloads `@preview` packages on import.
4. Users never write Typst source. Templates are generated by the server from a restricted, declarative
   model, and data is passed as JSON, never interpolated into markup.
5. Document size is bounded. The platform already caps a snapshot at 1000 rows and an artifact at 8 MiB;
   larger data is exported to Excel.
6. The Typst version is pinned by checksum, and every upgrade is gated by golden documents (page count,
   page breaks, text) and veraPDF.

## Evidence

Each option was measured with the same engine-independent checker and byte-identical input data
(synthetic statements of 150 to 30000 rows with hostile strings, punctuation-dense Chinese and a row taller
than a page), and both comparison documents were reviewed independently. The spike code and raw results are on
the local branch spike/typst-pdf (spikes/pdfgo/COMPARISON.md, spikes/typst/REPORT.md, spikes/pdfme).

| | Typst, breakable rows | fpdf, self-built layout | pdfme 6.2.8 |
|---|---|---|---|
| Hard thresholds (placement, carried totals, no silent loss, hostile text, GB/T 15834 line breaking, PDF/A-2b with veraPDF, determinism, fonts) | all met | met on the test data | silent truncation (2 of 120), PDF/A-2b fails, no carried totals, not deterministic |
| Characters outside the BMP | supported | process panics, including 445 the font covers | supported |
| Characters missing from the font | dropped silently | panic or `.notdef` | `\x00` |
| 30000 rows | 831 pages, 9.4 s, 2.8 GB | 1053 pages, 0.36 s, 0.2 GB | 1159 pages, 26 s, 2.1 GB |
| Code for the statement | 189 lines | 519 lines, plus typography still missing | n/a |
| Isolation | separate process | in-process | Node process |

The independent reviews corrected two claims of an earlier draft, and both corrections favour this decision.
Typst's silent truncation came from a template that made rows unbreakable; with breakable rows it meets every
hard threshold. The provisional memory and time thresholds were not blind, because they were set after the
first measurements. The code review judged the fpdf engine not fit for production: it panics on any character
outside the BMP, its upstream library has two trailer defects (a patch was prepared but not submitted), and
it lacks input bounds and overlap protection.

## Consequences

- An extra 56 MB static binary and fonts are deployed and verified by checksum; the renderer needs Linux user
  namespaces or a network-less container.
- Memory is about 3 MB per page. That is negligible under the 1000-row snapshot cap and must be revisited
  before any cap is raised.
- Typography (punctuation trimming, CJK–Latin spacing, table headers, page numbers) comes from Typst instead of
  project code.

## Revisit when

- A snapshot or document cap above about 300 pages is required, or the renderer's memory budget is below 1 GB
  per concurrent render.
- Typst changes its licence or governance, or an upgrade breaks golden documents in ways that cannot be fixed
  in the template.
- A format other than PDF, such as OFD (GB/T 33190), becomes mandatory.
